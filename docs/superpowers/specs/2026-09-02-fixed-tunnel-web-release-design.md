# 筑思 Agent 固定 Tunnel 网页发布设计

**日期：** 2026-09-02  
**目标：** 将当前单机双端口 Demo 收束为可通过固定 HTTPS 域名访问、可持续更新和可快速回退的校赛网页版本。  
**范围边界：** 本次只处理网页发布链路，不修改 Generator、Candidate Boundary、状态解析、专业经验边界或追问控制。

## 1. 当前数据与控制路径

当前运行链路为：

```text
浏览器 :8000/demo/collaborator.html
  ├─ 静态页面、案例图片 → Python http.server :8000
  └─ 对话、文件、视觉 API → server.py :8787
       ├─ 本地 BGE 向量检索
       ├─ Dify 知识库
       ├─ DeepSeek 文本生成
       └─ Qwen-VL 图像分析
```

前端通过 `location.hostname` 拼接固定的 `http://<host>:8787` 和 `http://<host>:8000`。后端允许 `Access-Control-Allow-Origin: *`。启动脚本分别启动两个 Python 进程，并检查两个端口。

## 2. 当前机制为什么不能直接作为固定公网网页

1. HTTPS 公网页面调用固定 `http://...:8787` 会触发浏览器混合内容限制。
2. 一个固定 Tunnel 主机名通常映射一个本地服务；当前网页和 API 分属两个端口，公开地址不统一。
3. 前端的端口拼接使公网域名仍尝试访问访问者本机或不可公开的 8787 端口。
4. 通配 CORS 对公网 Demo 过宽；同源发布后不再需要它。
5. 当前启动检查证明的是双进程本机 Demo，不证明固定域名、HTTPS、异网访问和模型链可用。
6. 直接复制整个工程会携带测试、日志、备份与本地实验文件；发布包需要显式清单，不能依靠排除猜测。
7. `.env` 虽已被 Git 忽略，但发布流程仍必须明确禁止复制或输出任何密钥。

## 3. 选定方案

采用“本机单进程同源服务 + Cloudflare Named Tunnel + 版本化发布”。

```text
访问者浏览器
  ↓ HTTPS 固定域名
Cloudflare Named Tunnel
  ↓ http://127.0.0.1:8787
筑思 Web 服务
  ├─ GET /                         → collaborator.html
  ├─ GET /demo/...                 → 前端资源
  ├─ GET /images/...               → 案例图片
  ├─ GET /api/health               → 服务健康
  └─ POST /api/...                 → 现有业务 API
```

Tunnel 只代理 `127.0.0.1:8787`。不开放路由器端口，不把 API Key 写入浏览器，也不把 `.env` 放入静态目录。

## 4. 最小工程修改

### 4.1 后端静态资源

在现有 `server.py` HTTP Handler 内扩展 GET 路由，复用现有进程：

- `/` 重定向或返回 `/demo/collaborator.html`。
- 仅允许读取发布根中的 `demo/` 与 `images/`。
- 进行路径规范化；拒绝 `..`、绝对路径、符号链接越界和未在允许目录中的路径。
- 返回正确的 HTML、JS、CSS、PNG、JPG、SVG 等 MIME 类型。
- 未命中资源返回 404，不回退到任意本地文件。

不新增 Web 框架或架构层。

### 4.2 前端同源化

- 对话 API 改为相对路径 `/api/architect_chat`。
- 文件、视觉和跨层分析 API 全部改为 `/api/...`。
- 案例图片改为 `/images/...`。
- 不再依赖固定的 8000、8787 或 `http://` 协议。
- 保留现有 `localStorage` 项目结构和导出行为。

### 4.3 启停链路

- 启动脚本只启动 `server.py --port 8787`。
- 健康检查同时验证 `/api/health` 和 `/demo/collaborator.html`。
- 停止脚本只处理本项目监听 8787 的 Python 进程，仍显示 PID 并要求确认。
- Tunnel 独立启动；应用启动成功后才允许启动 Tunnel。

### 4.4 发布包与回退

新增显式发布清单，只复制运行所需代码、`demo/`、`images/`、`knowledge/`、`vector_db/` 和配置示例。明确排除：

- `.env`、`*.key`
- 测试日志与真实对话记录
- `__pycache__`
- `_backup_*`
- 实验脚本、截图诊断文件和临时输出

每次发布生成带时间戳的版本目录和校验清单；`current` 指向最后一次通过验证的版本。新版本健康检查失败时不切换，已切换后失败则回到上一版。

## 5. 访问与费用保护

固定域名默认不等于完全公开：

- 测试入口使用 Cloudflare Access 限制指定访问者。
- 比赛入口只在演示窗口开放；演示结束后恢复限制。
- 后端保留上传大小限制，并增加请求体硬上限、并发上限和模型调用超时。
- 健康接口只返回能力是否可用，不返回密钥、完整上游地址或错误堆栈。
- 浏览器只展示可公开的失败信息，详细错误留在本机日志。

第一版不建设账号、数据库、用户权限系统或多人协作。

## 6. 更新流程

```text
开发目录修改
  → 自动测试
  → 生成候选发布包
  → 候选包本机启动
  → health + 主页面 + 浏览器 E2E
  → 切换 current
  → 固定域名抽查
```

前端或后端更新后域名不变。浏览器中的 `localStorage` 在存储键和结构不变时继续保留；任何存储结构修改必须先提供迁移测试。

## 7. 失败优先测试

实现前先增加以下失败测试：

1. `/` 与 `/demo/collaborator.html` 当前不能由 8787 返回页面。
2. 前端源码当前仍包含固定 8000/8787 和 `http://` API 拼接。
3. `/images/...` 当前不能由 8787 返回资源。
4. `../`、URL 编码越界和非允许目录必须返回 403 或 404。
5. 静态文件响应必须具有正确 MIME 类型。
6. 页面、API 与图片必须在同一 origin 下工作。
7. 发布清单不得包含 `.env`、密钥、日志、备份和历史用户数据。
8. 新单进程启动脚本必须同时通过健康和主页面检查。

## 8. 验证标准

自动验证：

- 新增静态路由、路径安全、前端同源和发布清单测试通过。
- 现有 Candidate、State、Semantic、Ledger 与比赛流程相关回归保持通过。
- 全量测试中的既有两项知识注释失败单独保留证据，不能把它们误归因于本次发布修改。
- Python 语法检查通过。
- 浏览器 E2E 验证页面加载、对话请求、图片资源、导出和移动端宽度。

真实验证：

- 本机访问固定域名成功。
- 使用另一网络的手机或电脑访问同一固定域名成功。
- 完成一次真实 DeepSeek 普通学生对话。
- 关闭后端时公网页面明确失败；恢复后可再次访问。
- 发布新版本后域名不变，失败版本可以回退。

## 9. 成功标准与停止条件

成功必须同时满足：

1. 一个 HTTPS 固定域名完成页面、API 和图片的同源访问。
2. `.env`、源码目录列表和历史数据均不能从网页获取。
3. 异网设备能够完成至少三轮真实对话。
4. 更新发布后网址不变，且可恢复上一版。
5. 人工阅读真实回答，不把“网页可访问”宣称为 Generator 质量问题已解决。

停止并报告，不继续绕过：

- 用户尚无可用于 Named Tunnel 的 Cloudflare 域名或授权。
- 当前网络阻止 `cloudflared` 建立连接。
- 单端口修改引入现有业务回归。
- 发布包需要包含密钥或用户历史数据才能运行。
- 异网验证只能打开页面但 API 或真实模型不可用。

## 10. 非目标

- 不修复 Generator 拒绝拓扑复活。
- 不修改专业经验事实化或追问控制。
- 不建设多用户数据库、正式账号与跨设备同步。
- 不把 Qwen-VL、DeepSeek 或 Dify 的调用成功伪装成本地能力。
- 不将 Quick Tunnel 的临时链接作为最终校赛固定入口。
