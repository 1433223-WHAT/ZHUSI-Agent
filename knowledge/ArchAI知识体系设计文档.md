## 一、定位

ArchAI 是**建筑设计辅助智能体**，不是建筑资料问答工具。

知识体系的唯一目的是支撑一个设计流程：

```
用户设计任务
     ↓
方法库（怎么做） ← ← ← ←
     ↑                   │
     │                   │
案例库（参考实例）── 理论库（为什么）
```

- **方法库** = 怎么做（设计操作手法）
- **理论库** = 为什么（支撑方法有效性的原理）
- **案例库** = 参考实例（方法在真实建筑中的体现）

用户不会先问"请给我建筑现象学"。用户会问"我要设计一个纪念空间"。
AI 需要：先判断要解决什么设计问题 → 然后调用方法 → 用理论解释 → 用案例佐证。

### 2.1 案例库（已有，补标签）

25 个案例已覆盖 5 位建筑师，**不再扩数量**。改造重点：给已有案例增加**统一结构化标签**，让 AI 能检索。

每个案例增加字段：
```markdown
## 设计问题
[这个案例解决了什么设计问题？]

## 核心方法
1. [方法1]
2. [方法2]

## 适用场景

- [场景2]

## 关联理论
```

### 2.2 理论库（新增 6 个理论卡片）

理论卡片格式 = **知识总结 + 设计应用**，不是论文堆积。

```markdown

## 核心概念
[3-5句话，讲清这个理论在说什么]

## 设计启示
- [如何应用于设计：路径制造时间感]
- [如何应用于设计：材料形成触觉记忆]
- [如何应用于设计：光改变空间情绪]

## 可用于
- [纪念空间]
- [展览建筑]

## 案例关联
- [光之教堂：十字光的精神性]
- [瓦尔斯温泉：石材的触觉]
```

### 2.3 方法库（新增 15-20 个方法卡片）← 核心竞争力

**设计方法库是 ArchAI 自己的设计逻辑**，是区别于 ChatGPT 的关键。
方法卡片格式：

```markdown
# 方法名

## 核心逻辑
[一句话讲清这个方法做什么]

## 操作方式
1. [步骤1]
2. [步骤2]
3. [步骤3]

## 适用场景
- [纪念建筑]
- [教堂]

## 案例来源
- [光之教堂：入口压缩→核心释放]
- [萨伏伊别墅：坡道漫游]
```

**第一批方法类别**（3-5 类 × 每类 3-5 个 = 15-20 个）：

| 类别 | 方法示例 |
|------|---------|
| **空间序列** | 压缩—释放 / 空间嵌套 / 轴线递进 / 螺旋上升 |
| **动线与体验** | 漫游式路径 / 仪式性动线 / 视线引导 / 转折延迟 |
| **光环境** | 单一光源 / 天光漫射 / 光缝引导 / 明暗对比 |
| **材料策略** | 单一材料纯粹 / 材料对比 / 新旧对话 / 地域材料 |
| **场地应对** | 底层架空 / 嵌入地形 / 覆土 / 借景 |
| **空间体验** | 尺度压缩 / 高度落差 / 触觉表面 / 声音引导 |

## 三、AI 如何调用这三层

```
用户："设计100㎡校园纪念空间"
    ↓
1. 任务理解：纪念空间 + 100㎡ + 校园
    ↓
2. 检索案例库：→ 光之教堂（精神性空间）、水之教堂（自然介入）
    ↓
3. 调用方法库：→ 压缩—释放序列（操作步骤）
    ↓
4. 用理论解释：→ 空间序列理论（为什么这样有效）
    ↓
5. 生成方案：面积表 + 空间组织 + 材料 + 光环境
```

**回答中体现三层**：
- 案例佐证："参考光之教堂的入口压缩手法"
- 理论支撑："依据空间序列理论，过渡空间制造心理转折"
- 方法操作："降低入口高度→延长路径→转折→核心释放"
